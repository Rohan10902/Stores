# StoreLens 7.2.1

StoreLens is a local-first Windows desktop application for reviewing, validating, repairing, comparing, analysing, and creating structured store datasets.

## Production principles

- Source files remain unchanged unless the user explicitly exports a new file.
- Processing is local to the workstation.
- Store matching is identity/key based rather than row-position based.
- Repeated SIDs can be legitimate; Nielsen Store Code can be used as an additional identity key.
- Store-file creation uses the fixed 14-column output schema defined in `core/common.py`.
- Nielsen Store Code leading-zero changes are previewed before application and only all-digit identifiers are padded.
- Validation failures remain visible instead of being silently discarded.
- CSV repair preserves unresolved values and requires explicit review before export.

## Supported input

The application core supports CSV, TSV/text, Excel (`.xlsx`, `.xls`, `.xlsm`), JSON, and XML where the required pandas reader is available.

## Development

Requires Python 3.12.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python app.py
```

## Tests

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
```

The Windows CI compiles and imports the complete Python source, runs regression tests, parses every QML file, starts the real StoreLens UI offscreen, builds the Windows executable, starts the packaged executable, generates a SHA-256 checksum, and only then publishes the testing artifact.

## Windows build

The official testing artifact is generated by `.github/workflows/build-windows.yml`. A successful PyInstaller command alone is not a pass: the packaged executable must also complete its startup probe.

## Logs

Runtime diagnostics are written under the local StoreLens log directory. QML startup errors are also emitted to CI stderr so startup failures can be diagnosed directly from the workflow logs.

## Release policy

`main` is the stable StoreLens source line. Production release should follow a successful end-to-end Windows CI run and hands-on testing of the generated artifact.
